# 完整行业、基本面与多周期缠论实施计划

## 目标

把当前“单周期候选 + 行业标签 + 基本面未接入”升级为可审计的行业、基本面/估值和
weekly/daily/120m/30m/5m 多周期证据链。任何证据缺失、未来、陈旧、未闭合或不一致时，
full_analysis_ready=false、multi_cycle_confirm=false、新增仓位为 0，自动交易始终关闭。

## 原则

1. 数据事实、模型分析和交易动作分层；provider 成功不等于门禁通过。
2. 所有证据携带来源、数据时点、采集时点、截止时点、状态和稳定错误码。
3. 高周期约束低周期；5m 只能优化执行，不能独立把 WAIT 变成 BUY。
4. 股票、ETF、指数和基金适用不同基本面/估值契约。
5. 不新增依赖；复用现有 AkShare/Tushare、KLine、分钟闭合和七道门。

## 决策记录（ADR）

- 决策：先建立统一证据契约和失败门禁，再接数据源。
- 驱动因素：避免未来数据污染、避免分钟闭合冒充结构确认、保持现有 API 兼容。
- 未采用：直接在报告层计算评分；原因是无法审计来源和截止时点。
- 未采用：把持仓 sector 标签作为行业强弱；原因是它只描述暴露，不是市场横截面。
- 后果：前几个切片仍会输出 WAIT，但每个缺口都有稳定、可测试的原因。

## 阶段

### 0. 统一证据契约与 WAIT 门禁

- 新增不可变证据状态模型：READY/DEGRADED/NOT_READY/FAILED；
  RECENT/DELAYED/STALE/FUTURE/UNKNOWN。
- 严格校验 timezone-aware 时间、source、market_date、cutoff、未来数据和错误码。
- 基本面、估值、行业、结构证据必须显式通过；缺失/异常不能由技术分补偿。
- 接入 portfolio 分析的 full_analysis 摘要，但默认不改变既有报告动作。
- RED 测试：未来、陈旧、未知状态、缺字段、truthy 字符串、部分覆盖、异常对象。

### 1. 基本面与估值

- 新增 provider-neutral 股票/ETF 证据模型和 AkShare/Tushare 适配器。
- 股票最低字段：报告期、发布日期、营收/利润质量、ROE、PE/PB；
  ETF 使用规模、净值日期、跟踪标的、折溢价，不套股票财报。
- published_at 晚于 cutoff、无发布日期、陈旧估值、非法数值全部失败关闭。

### 2. 动态行业排序

- 接入统一日期的行业行情横截面，不用持仓标签推导强弱。
- 最小评分只含相对收益、趋势、活跃度和覆盖完整度。
- 部分行业失败为 DEGRADED；关键字段缺失时不生成排名分数。

### 3. 周线与日线闭合

- history loader 支持 weekly 与 daily，分别校验顺序、重复、未来和闭合。
- 每周期独立保存 source/as_of/status/freshness；周线缺失不能提升整体确认。

### 4. 五周期缠论聚合

- 对 weekly/daily/120m/30m/5m 分别运行现有 analyze_chan。
- 周线=位置、日线=方向、120m=核心结构、30m=回调确认、5m=执行优化。
- 任一必要周期非 CLOSED、数据缺口、时间错位或反向结构，确认必须为 false。
- 同一标的/中枢/结构指纹不得重复触发新增仓位候选。

### 5. 报告、七道门和合成验收

- 报告明确区分事实、分析、缺口、人工复核条件和最终动作。
- 14:30 下午 120m 未闭合时固定 WAIT；收盘后也只在全部证据完成时标记确认。
- 全量覆盖、异常隔离、五日重复二买、跨午休、未来时间、供应商失败回归。

## 验收

- 新测试先 RED，再最小实现 GREEN；全量现有测试保持通过。
- auto_execute 始终 false；任何缺失保持 WAIT/HOLD。
- 只有全部必要持仓和全部证据通过，full_analysis_ready 才允许为 true。
- 本计划不承诺数据供应商 SLA、缠论交易级准确率、私有账户上线或五日真实验收完成。
