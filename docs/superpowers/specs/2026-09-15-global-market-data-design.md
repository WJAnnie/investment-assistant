# 隔夜全球市场数据接入设计

## 目标与边界

为 09:00 晨报接入可追溯的公开全球行情，覆盖八个观测标的、七类市场：

- 美股：标普 500、道琼斯工业指数；
- 纳斯达克：纳斯达克综合指数；
- 半导体：费城半导体指数；
- 美债：美国 10 年期国债收益率；
- 美元：美元指数；
- 黄金：COMEX 黄金期货；
- 原油：WTI 原油期货。

本次只解决公共行情采集、校验、存档和用户可读展示。它不读取真实持仓，不计算买卖评分，不改变 `WAIT / 人工确认 / 禁止自动交易` 的安全边界，也不把公开源标记为官方认证或实时行情。

## 方案选择

采用用户确认的方案 A：Yahoo Chart 无密钥接口作为八个标的的主数据源，美国 10 年期国债收益率增加 FRED 官方日频数据作为定向兜底。

固定代码映射为 `^GSPC`、`^DJI`、`^IXIC`、`^SOX`、`^TNX`、`DX-Y.NYB`、`GC=F` 和 `CL=F`。适配器必须核对响应中的代码，不能接受服务端静默替换的近似标的。

未采用带密钥商业 API，因为当前公开 GitHub Actions 明确隔离采集步骤与 Secrets，且尚未确定具备相同八标的语义和许可的供应商。未采用 EastMoney、Sina 或 Stooq 多源拼接，因为本轮实测存在断连、403 或 404，并且不同源的合约、收盘和涨跌语义不一致。

Yahoo 是未经项目认证的公共数据源，可能限流或改变响应结构。因此系统必须逐标的失败关闭，不能因成功请求就声称数据已验证。FRED 仅兜底美国 10 年期收益率，不伪装成盘中实时数据。

## 组件与接口

新增独立的全球市场适配器，不扩张现有只面向国内指数的 `SinaProvider`。适配器公开一个可注入、可离线测试的批量采集接口，并返回固定顺序的观测记录。

每条记录包含：

- 固定类别、代码和用户可读名称；
- 最新值、比较基准和变化值；
- 变化单位：指数、美元、黄金和原油为 `%`，美国 10 年期收益率为 `bp`；
- 数据源、行情时间、会话日期和新鲜度状态；
- 固定错误码，不包含远端异常文本、URL、响应体或凭据。

美国 10 年期收益率的 `value` 表示收益率百分数，例如 `4.96` 表示 `4.96%`；变化量按 `(当前收益率 - 前值) × 100` 转换为基点。其他标的变化量按 `(当前值 / 前值 - 1) × 100` 计算。

## 数据流与快照迁移

09:00 晨报采集流程为：

1. 在任何网络请求前校验阶段、时间和输出目录；
2. 国内指数继续由新浪适配器采集；
3. 全球适配器逐标的请求、解析和校验 Yahoo 响应；
4. 美国 10 年期主源失败时，单独尝试 FRED 最近两个有效观测值；
5. 生成严格的 `public-trial/v2` 快照；
6. 先验证快照，再生成 README 和飞书通知；
7. 通知发送失败不回写或伪造行情结果。

`v2` 将全球行情作为快照中的独立顶层对象，确保公开数据分支能够审计通知所依据的原始结构。读取端在迁移窗口内允许严格校验旧 `v1`，写入端只产生 `v2`。旧 `v1` 晨报仍显示“未接入”，不能被渲染器补造为已采集；各时点被新任务覆盖后，公开分支自然完成迁移。

全球行情只在晨报阶段发起外部采集。午盘、14:30 和收盘快照保留明确的“本阶段未采集”状态，不重复请求海外接口，也不把早晨数据描述成盘中更新。

## 时间与新鲜度语义

行情时间使用数据源返回的 Unix 时间转换为带时区的 ISO 8601，禁止使用程序生成时间冒充行情时间。会话日期从行情时间和标的市场时区推导，与晨报日期分开保存。

系统不自行猜测海外交易日历。只计算数据年龄并输出保守状态：

- `RECENT`：行情时间不超过采集时间 36 小时；
- `DELAYED_OR_HOLIDAY`：行情时间超过 36 小时但不超过 120 小时，可能来自周末、节假日或源延迟；
- `STALE`：行情时间超过 120 小时，只展示日期和风险提示，不参与强弱判断；
- `UNKNOWN`：源未提供可验证时间；
- `INVALID`：行情时间晚于采集时间 5 分钟以上、非法时间或字段矛盾，整条记录失败关闭。

FRED 只有观测日期时，以日期字段保存 `session_date`，并把时效计算到该日期的上海时间 23:59:59；不得编造盘中时分秒。

用户文案显示“截至某时的最近可得数据”，不使用“实时”“已验证”等无法证明的措辞。黄金、原油和美元可能处于连续交易时段，展示为“最新报价相对前值”，不冒充完整收盘涨跌。

## 异常与安全边界

以下情况按单标的隔离：10 秒超时、429、非 200、重定向、超过 1 MiB 的响应、非法 JSON、返回代码不匹配、缺失价格或前值、零或负基准、NaN/Infinity、异常时间戳和异常涨幅。采集阶段不自动重试，避免八个失败请求把定时任务拖成长时间阻塞。一个标的失败不阻断其他标的；全部失败时晨报仍可发送，但必须明确写为全球行情不可用并保持 `WAIT`。

所有远端错误统一映射为固定错误码。公开快照、日志和通知不得保存请求头、代理信息、完整 URL 查询、响应片段或异常原文。HTTP 会话继续禁用环境代理和 `.netrc` 隐式凭据，并阻止重定向。

数据完整度只分为完整、部分和不可用。只有八个标的都通过字段及时效校验时才是完整；任何缺失都不能据此自动推导“科技偏强”“风险低”或行业排序。

## 展示

晨报首先给出“隔夜全球市场”区块，逐行展示名称、最新值、变化单位和数据时间。示例：

```text
🌍 隔夜全球市场
标普500：7,619.98（-1.28%）｜截至 09-14 16:00 美东
美国10年期国债收益率：4.96%（+1.1bp）｜数据日 09-11
WTI原油：103.10美元（+0.60%）｜最新报价
```

部分失败时只在对应行显示“暂不可用”，并在区块末尾说明完整度。执行模式、内部状态枚举和 provider 名称不直接暴露给用户。

## 测试与验收

按 TDD 逐条锁定以下公开行为：

1. 八个正常 Yahoo fixture 能生成正确单位、涨跌和时间；
2. 美国 10 年期按基点计算，主源失败时只调用 FRED 兜底；
3. 单标的 429、超时、空值、非法数字、代码错配和坏时间不影响其他记录；
4. 周末或较旧数据不会被标记为实时，未来时间被拒绝；
5. `v2` 严格拒绝额外字段、错误类型、任意错误文本和交易动作；
6. 旧 `v1` 可严格读取但不会被伪装为已接入；
7. 飞书文案包含数据时间和用户可读单位，不出现内部枚举或执行日志；
8. GitHub sparse checkout 包含新增模块和测试，采集步骤仍不引用 Secrets；
9. 离线单元测试不联网，另用显式只读 smoke test 验证真实端点可访问性。

完成标准是：离线测试、编译和静态检查通过；真实网络 smoke test 至少能得到部分有效全球行情；模拟 429 和全源失败时仍能生成明确降级的 `WAIT` 晨报。真实网络的某次成功不构成长期可用性或行情正确性保证。
