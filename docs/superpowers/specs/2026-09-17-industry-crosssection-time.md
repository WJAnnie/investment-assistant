# 行业板块截面「时间戳不一致」问题：实测证据与待决选项

状态：**已决（采纳选项 2：截面窗口放宽至 MAX_CROSS_SECTION_WINDOW = 240s，as_of 归一为窗口终点 max(present)，报告如实披露截面窗口，坚决不采纳多数派子集与本地时钟伪装）**。

## 现象

09:00 晨报的行业排序在真实公网路径上稳定输出失败行
（`status=FAILED, error=NO_USABLE_DATA` / 原因文案「行业数据不足或已过期」），
即使分页完整性已修复（每次均为 496/496 个板块、无重复、无丢失）。

## 三处已修复的缺陷（已提交，非本文讨论范围）

| 提交 | 缺陷 |
|---|---|
| `d2b8cd4` | 有界收敛的重抓把「空响应」写成空页，静默删除整页已抓到的行；若幸存页恰好互相一致，残缺榜单会被当作 READY 发布 |
| `7f324b0` | 排序键 `fid=f3`（涨跌幅）盘中持续变动，导致翻页重复/丢行：实测每轮丢失 18–35 个板块；改用稳定唯一键 `fid=f12` 后为 496/496 |

## 本文记录的根因：该接口的截面时间戳本质不可收敛

数据源：`https://push2delay.eastmoney.com/api/qt/clist/get?fs=m:90+t:2`，`pz` 被服务端硬性钳制为 100，
`_MAX_PAGES=8` 才能取全 496 个板块。

`AkShareIndustryProvider.fetch()` 有一条**刻意的诚实规则**：整批只要任意两行的 `数据时间` 不一致，
就整批判 `ERROR_DATE_MISMATCH`、0 条观测。于是该规则能否通过，取决于一次 8 页扫描能否
拿到**单一时间戳**的完整截面。

### 实测结果（2026-09-17 盘中，Asia/Shanghai）

| 观测 | 结果 |
|---|---|
| 单页内的 `f124` 分布 | 常为 1 个值，也常为 2–6 个值（同一次响应内部就不一致） |
| 整轮 8 页扫描的不同 `f124` 个数 | 6–19 个（20 轮全部不一致，**0/20 收敛**） |
| `f124` 跨度 | 63–204 秒 |
| 主导戳占比 | 30%–60%（最近一次实测 38%） |
| 固定一页连续取 3 次，同一板块的 `f124` 是否单调不减 | **100/100 不单调**（会回退到更早的值） |
| 单页连续 20 次采样，戳是否变化 | 19 次里变化 17 次 |

「同一板块的时间戳在连续请求中会回退」说明：服务端按页缓存，不同请求命中的是**不同的缓存批次**
（撕裂快照），而不是行情本身回退。因此：

- 收敛能否成功取决于 8 页是否命中同一批次；
- 概率很低且不可控：实测稳定路径下 **1/10** 成功（修复前 3/12）；
- 重抓只是换一批随机批次，不能构成稳定的收敛保证。

该接口在修复后平均每轮发出 11–18 次请求，其中绝大多数是无效重抓。

## 待决选项（按推荐度排序）

### 选项 1（推荐）：把行业采集移出 09:00，只要求「可发布性」而非「单一戳」

- 现状：只有 `stage == 'morning'` 才采集行业（`public_trial.py:452`），09:00 恰好是该接口缓存撕裂最严重的时段之一；
- 但实测 09:32 同样是 0/20 收敛，所以**单纯延后时间不足以解决问题**；
- 因此本项必须与「戳语义」一并决策，不能单独实施。

### 选项 2：承认戳语义不匹配，放开「单一戳」要求，改为可验证的截面窗口

把「全部行必须同一戳」改为「全部行必须落在同一可接受时间窗口内」，并**公开披露**窗口起点终点，
从而：
- 保持 496 个板块的完整覆盖（不丢板块、不伪装完整）；
- 仍然拒绝过期数据（窗口外一律判 `DATE_MISMATCH`）；
- 代价：`as_of` 语义从「单一快照时刻」放宽为「窗口」，需要在 schema 与文案中如实表达。

> 这需要一份明确决策记录，因为它修改的是既有的诚实规则本身，而不是修 bug。

### 选项 3：接受现状，保留诚实失败行

不改任何行为，晨报继续输出「行业数据不足或已过期」。数据可靠但行业排序长期缺失。

### 选项 4：更换数据源

改用不提供 `f124`（或提供统一快照时间）的行业板块接口。需要重新评估可得性、许可与字段语义。

## 明确不采纳

- **多数派子集**：只保留占比最高的戳（实测仅 30%–60%），会给用户一份**残缺却看起来完整**的榜单，
  且不触发任何失败标记。这正是 `d2b8cd4` 修掉的那类缺陷。
- **用本地抓取时间冒充数据时间**：违背提交 `58c06b3`「采集源自身的时间，而不是凭空编造」的既定决策。
- **无限重抓**：实测收益率极低（1/10）且请求量翻倍以上。

## 与安全边界的关系

以上全部只影响**分析质量与展示**，不触及交易。系统仍为
`分析=自动 / 提醒=自动 / 交易=人工确认`，`auto_execute` 恒为 `False`。
行业排序长期缺失**不会**产生任何错误交易指令，只会让晨报少一个模块。
